# WorKey 대시보드 동기화 검증 프로토콜

대시보드의 "동기화" 버튼이 생성한 검증 요청을 처리하는 표준 절차.
어떤 세션이든 이 파일의 절차를 그대로 따른다. 세션별 임의 판단으로 절차를 생략하지 않는다.

## 기준 경로

**워크스페이스 루트 = 이 파일이 있는 `dashboard/` 디렉토리의 상위 디렉토리.**
아래 모든 경로는 워크스페이스 루트 기준 상대경로다.

| 산출물 | 경로 |
|--------|------|
| SSOT (마스터 검증 문서) | `docs/WorKey - 전체 진척도.md` |
| 추적성 인덱스 | `SSOT-CODE-TRACEABILITY.md` |
| 백엔드 소스 | `backend/` (→ workey-api, 헥사고날: presentation/application/adapter) |
| 프론트엔드 소스 | `frontend/` (→ workeyApp, `src/features/*`, `src/shared/api/endpoints.ts`) |
| live OpenAPI | `http://localhost:9090/v3/api-docs` |
| 시드 재생성 | `python3 dashboard/generate_seed.py` (워크스페이스 루트에서) |

## 검증 절차

1. **앵커 확인**: `SSOT-CODE-TRACEABILITY.md`에서 대상 ID의 코드 앵커(백엔드 Controller→UseCase, 프론트 hook/screen)를 찾는다.
2. **레벨 분류**: 아래 검증 레벨 표에 따라 이 항목에 필요한 검증 수단을 정한다.
3. **검증 실행**: 해당 레벨의 방법으로 SSOT 세부사항의 "완료 기준"을 하나씩 대조한다.
4. **판정 보고**: 출력 형식에 맞춰 보고한다.
5. **SSOT 갱신**: 체크 상태 변경이 필요하면 사용자 승인을 받은 뒤 `docs/WorKey - 전체 진척도.md`의 해당 체크박스와 "현재 상태" 서술을 갱신한다.
6. **재시드**: SSOT를 갱신했다면 `python3 dashboard/generate_seed.py`를 실행한다.
7. **대시보드 SYNC 블록 갱신**: 판정이 "완료 확인" 또는 "미완료"로 확정되면 `dashboard/index.html`의 `/*SYNC_START*/ ... /*SYNC_END*/` 블록에 디렉티브를 기록한다. 이 갱신은 프로토콜로 사전 승인된 동작이며 별도 승인이 필요 없다.
   - 형식: `"<ID>": { "status": "<done|todo|in_progress>", "at": "<현재 시각 ISO8601, 예: 2026-06-13T01:30:00+09:00>" }`
   - status 값: 완료 확인 → `"done"`, 미완료 → `"todo"` (작업 진행 흔적이 명확하면 `"in_progress"` 가능)
   - **판단 불가면 기록하지 않는다.**
   - 기존 다른 ID의 디렉티브는 보존하고, 같은 ID는 덮어쓴다. `const SYNC = { ... };` JS 객체 리터럴 형식을 유지한다.
   - 대시보드는 로드 시 이 디렉티브를 자동 적용한다. 단 디렉티브 시각(`at`) 이후의 사용자 수동 변경은 덮어쓰지 않는다.
8. **반영 안내**: "대시보드 새로고침하면 자동 반영" 한 줄로 안내한다.

## 검증 레벨

| 레벨 | 대상 | 방법 | JWT |
|------|------|------|-----|
| L1 코드 검증 | 구현 존재/배선 여부 | 앵커 코드를 직접 읽고 확인. grep만으로 끝내지 말고 호출 흐름까지 확인 | 불필요 |
| L2 계약 검증 | OpenAPI path/method 존재 | `GET http://localhost:9090/v3/api-docs` 호출. **404 또는 연결 실패 시 백엔드 미구동을 보고하고 L2 검증을 중단** (워크스페이스 규칙) | 불필요 |
| L3 무인증 동작 | 401/403 응답 계약류 | 토큰 없이 보호 API 호출 — 무인증 자체가 테스트 | 불필요 |
| L4 인증 동작 / 실행 evidence | 인증 필요한 live 동작, FCM 실기기, TTI, CI run | (a) 기존 자동화 테스트 실행 결과를 evidence로 사용 (테스트 컨텍스트가 토큰을 자체 생성), 또는 (b) evidence 파일(`*-VERIFICATION.md`, `*-LAUNCH-EVIDENCE.md` 등)의 존재와 내용 확인. 둘 다 불가하면 **"판단 불가 - live UAT 필요"로 정직하게 판정** | 테스트 내부 |

### 금지 사항

- dev 토큰 백도어(`/dev/token` 등) 생성·부활 금지. 보안상 제거된 것이다 (MVP-BE-003/010).
- 코드 구현 존재만으로 evidence류 항목(L4)을 완료 판정하지 않는다.
- SSOT 문서 서술만 보고 완료 판정하지 않는다. 최소 조합 = 문서 + 코드 + (계약 항목이면 live OpenAPI 또는 실행 evidence).
- 사용자 승인 없이 SSOT를 수정하지 않는다.

## 판정 출력 형식

```
[동기화 검증 결과] <ID>
판정: 완료 확인 | 미완료 | 판단 불가
근거:
- <확인한 파일:라인 또는 OpenAPI path, 무엇을 확인했는지>
- ...
SSOT 조치: 변경 불필요 | [ ]→[x] 갱신 제안 | [x]→[ ] 갱신 제안
SYNC 기록: <기록한 디렉티브> | 기록 안 함(판단 불가)
대시보드 반영: 새로고침하면 자동 반영 | <판단 불가 시 필요한 것>
```

## 판정 기준

- **완료 확인**: SSOT 세부사항의 완료 기준 전부가 코드/계약/evidence로 충족.
- **미완료**: 완료 기준 중 하나라도 미충족이 확인됨. 무엇이 빠졌는지 명시.
- **판단 불가**: 검증 수단이 막힘 (백엔드 미구동, evidence 부재, live UAT 필요 등). 무엇이 있어야 판정 가능한지 명시.
